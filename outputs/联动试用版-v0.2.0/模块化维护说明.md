# 模块化维护说明

当前维护入口：`C:\Users\hp\Documents\Codex\2026-11-01\new-chat\work\integration`。

`config.json` 选择版本号和启用模块；`modules` 内每个 JSON 是一个功能的正式源码。`build.cjs` 负责生成游戏文件，`verify.cjs` 负责本地静态核对。上一版的 `work/build-integration.cjs` 仅保留为历史文件，不再用于第二阶段维护；`work/prepare-stage2-source.cjs` 是已执行的一次性迁移工具，不要再次执行来覆盖新源码。

| 模块 | 维护内容 |
|---|---|
| ammunition | 两种弹壳与装填配方 |
| monster_materials | 暗金属、怪物皮装备材料 |
| dimension_materials | 稳定构造装备材料 |
| city_supplies | 城市补给与箱子分配包装 |
| resource_processing | 暗金属碎片压制、电弧炉冶炼 |
| astral_fiber | 星纤维物品、两条加工配方、材料定义 |
| apotheosis_support | 符石坯片与两类工业符石 |
| mutant_parts | 突变肢骨杆件材料 |
| field_guide | 指南入口及原有金属联动提示 |

每个模块声明依赖模组、自己的物品、配方、材料、语言、提示和指南页面。当前模块间没有必须同时启用的自定义物品依赖；共同引用原生物品不会强制绑在同一个模块。生成器检查重复输出、缺失的自定义物品和显式模块依赖。依赖列表不是自动安装模组的功能。

运行以下命令从本项目目录生成本版：

```powershell
node .\work\integration\build.cjs
node .\work\integration\verify.cjs
```

静态检查依赖同一 `work` 目录保留的模组核查缓存、第一阶段清单和修正后的离线探针源码。它不会启动 Minecraft，也不会执行探针。生成器本身只需要 `integration` 目录。

新的版本应修改配置版本号并生成新的输出目录，以保留旧版交付与撤回资料。生成器发现输出目录里有已不属于当前模块组合的旧文件时会停止，不会把这些文件悄悄混入新包。

改变模块组合后，应使用上一版清单计算升级差异。`work/install-stage2.ps1` 接受安装包、上一版安装包与实例路径参数，能备份被更新/撤下的已管理文件；只允许覆盖与上一版指纹一致的文件。不要在正常游戏实例随意关闭已经用于存档装备的材料模块。

共享游戏脚本是生成结果，多个源码模块可以共同拥有它。修改数值或配方时编辑对应模块，再生成安装包；直接编辑输出脚本会在下一次生成时被覆盖。客户端和服务端应使用同一套发布文件。
