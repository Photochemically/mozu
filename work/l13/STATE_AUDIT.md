# 实例与多人状态快照

2026-11-04。代码已编译、4项快照逻辑测试通过；当前实例未安装桥接，尚不能在当前游戏使用，也未实际执行。

## 命令

管理员权限等级至少2：

```text
/expedition audit snapshot
/expedition audit snapshot <实例UUID>
```

第一条导出全部实例，第二条只导出指定实例及其传送操作。一次最多2000个实例、10000条传送操作，超出则要求指定实例，不悄悄截断结果。无论哪种范围，都会记录当前在线玩家的位置和已加载维度概况。

输出位于该世界 `expedition_reports/state-<唯一ID>.json`，保留每次快照以便重启前后或两人分步操作后比较。写入先使用临时文件，再替换为报告文件；不自动发送报告，不复制整座世界。

## 已能看到的内容

- 实例UUID、门种类、生成阶段、实际等级、已选建筑、入口、预留范围、重进位置与出口记录。
- 原生内部连接以internalLinks单独记录源端和目标端，不混入主世界出口exits；这仍是保存的记录，不是实时方块核查。
- 每名参与者的进入／活动／断线／等待重生／安全离开状态、返回锚点、是否暂离到生活空间。
- 特殊门为何尚不满足关闭条件：未实际抵达、尚有人未安全离开、暂入生活空间，或当前阶段不符合；普通探索门标记为永久入口。
- 已保存传送操作UUID、进入／离开路线、边狱抽取结果、准备／落地状态、落点和释放时间。读取不会再抽概率。
- 已记录的首领完成标识、实际维度类型／高度、当前加载区块数量、原版强制加载区块数量、在线玩家位置和相关版本／开关。

## 不能据此宣布通过的事项

报告固定 `runtimeAcceptancePassed=false`。它记录当前服务端内存，不强制保存，也不从磁盘重新加载一份状态；重启恢复需要在真正重启前后分别导出并比较。

不扫描宝箱内容、建筑方块或实际裂隙目标，不测落点安全、不传送玩家、不触发生成，不修改门或参与者。首领完成标识只代表已有字段，首领最终死亡与发奖机制尚未完成。加载统计中的原版强制区块数不覆盖所有模组票据，不能据零值宣称没有持续加载。

正常存档加载仍由原有服务负责；中断生成的隔离规则不被诊断命令绕过。预置测试场、强制边狱测试输入、完整首领诊断、宝箱前后自动对照、总验收报告和收集包仍待开发。

## 双人验收用法

在两人入门后、一人离开后、另一人暂入生活空间后、全员安全离开后分别导出；玩家只需报告对应操作与异常。开发读取快照解释参与者和关闭判定，并结合实际入口是否消失及日志进行验证。
