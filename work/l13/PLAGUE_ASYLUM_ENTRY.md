# 瘟疫疯人院：地下原房间入口

更新：2026-11-19。锁定 WDA 2.1.58 的 `dungeons_arise:plague_asylum`；代码与原模板静态检查阶段，未安装、未启动 Minecraft。

## 原图与岩层

原目录有 33 份模板：五种走廊、三种通道、七种房间、七种普通病房、五种安全病房和六种刷怪附件。原唯一起始件为 `plague_asylum_corridor_4_crossing_pit`，原池 `dungeons_arise:haunted/plague_asylum/plague_asylum_start`，size=7、最大中心距离 104；起点绝对高度 0，不投影到高度图。锁定的原版 JigsawPlacement 扣除 groundLevelDelta=1 后，首件原点 Y=-1；环境地表高度不能替代该绝对起点。

只接受 `rock/start_room`，不从岛面挖新通道。仍由原生成器选择完整组件图，本适配只核对模板、尺寸、刚性投影、原连接方向和实际已选组件的连通性。原池为空回退，未选中的可选分支允许留空，不强制生成全部房间或刷怪附件；已选图不得断开、错位、重复或丢失刷怪数据。

原 corridor_1_cells 内已有两间默认病房和占位宝箱，选中的普通病房按原顺序覆盖对应默认病房。七种普通病房均完整写入 8×7×9=504 格；运行前核实完整写入范围，只允许合法原接口内的对应占位宝箱被替换，按最后实际选中内容检查。替换为空气、家具或带战利品表的箱子均沿用原生结果；其他设备覆盖仍拒绝。

`terrain_adaptation=bury` 使原 StructureStart 的完整范围比组件并集各方向扩展 12 格，此范围完整保留。原建筑整体放入岩岛，完整范围顶端上方至少四格岩石；底部支撑和空间隔离继续由原岛屿及预留逻辑处理。地表高度仍是显式配置，不擅自抬高、压缩建筑或删除深层。整体搬迁同时移动建筑、房间、连接和检查坐标，存档格式仍为 5。

## 入口、出口和原内容

施工完成后先分批核对原宝箱/木桶战利品表、发射器物品、刷怪设置和水源，再使用原房间的水平空气接口搜索安全落点。首个位置必须属于原起始房间；其余出口优先分散到较远的不同原房间，数量按既有候选配置为 1～4，彼此保持至少八格曼哈顿距离。安全支撑、身体净空和门的空气位置沿用现有规则，安装前再检查；不挖墙、填坑、替换铁栏或机关，也不因位置不足而减少出口数。

所有门沿用玩家各自的主世界返回锚点及已确认边狱规则，重新进入仍从保存的起始位置开始。一次生成后不重建，不刷新宝箱或首领状态。普通玩家仍可按既定规则改变非受保护建筑。

原陷阱包括唤魔者尖牙刷怪设施和迟缓药水发射器；原敌人含带装备与效果的“瘟疫医生”骷髅、凋灵骷髅、女巫和尸壳群。保留原 SpawnData、SpawnPotentials、间隔、数量及激活范围。原尸壳附件 SpawnCount=20，本批保留原配置，正式双人强度与数量控制尚未完成，不能据此宣称已经平衡。原储藏、药水、普通、病房和宝藏战利品表继续使用。

原水源在施工阶段暂存流体 tick，检查后按已有预算释放。宝箱首次放置的随机种子、刷怪倒计时沿用原版，不与模板常量作错误比较。装饰、床、告示牌、酿造台和漏斗交由原模板放置；本批不删改，但没有把每项动态设备状态都视为不可变校验对象。

## 证据与集中验收

本批八项新测试通过，最终完整 build 和 319 项 Java 回归通过。56 组原件图覆盖全部 33 模板、四旋转、14 种分支/装饰循环和 1～4 个出口，每组含 21～35 件及 14～29 个最终内容核对点。

测试使用原 JAR 的组件与接口拼装代表性分支，模拟完整岩层背景，调用生产选址和内容检查；不是在世界中运行原生随机生成器。当前结果以 `audit/build-summary.json` 和 `audit/plague-entry-audit.json` 为准，原始构建日志仅本地保存。

集中实机至少检查：完整随机图及拒绝率；原起始深坑旁实际落脚；楼梯/双层房间与病房之间通行；原尖牙、药水和骑乘配置；水流释放；1～4 处出口及双人返回；改建、开箱、离线与重启后的持久化；完整岩岛首次施工负载。静态选址只证明各门位与其原房间接口相连，不证明每个房间之间均可无挖掘通行。正式池、自然入口和怪物模组平衡尚未开启。
